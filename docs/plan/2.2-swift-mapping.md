Step 1 of the Swift unit: the mapping spec only, with no emitter code. The emitter
(`tools/aimux-codegen/src/emit/swift.rs`) comes next and implements exactly
this table. Everything here is derived from the same wire IR the Go emitter
consumes, so the two emitters cover the same constructs.

## Output shape

- One Swift module source tree under `target/codegen-out/swift/` (`Types.swift` + `Runtime.swift`, plus `Package.swift` for the harness). It is written only through `emit::write`, so the guard applies unchanged: no path under `bindings/`, no symlink below the root, relative roots made absolute (emit/mod.rs:35-80).
- Every type is `public`, `Codable`, `Equatable`, `Sendable`. Only Foundation is used (`JSONEncoder`/`JSONDecoder`), so it builds with swift-corelibs-foundation on Linux and with Foundation on macOS.
- Type names are the IR names. Field identifiers are lowerCamel of the Rust name, with Swift keywords back-ticked. Wire keys always go through explicit `CodingKeys` raw values, never `keyEncodingStrategy`.

## Mapping table

### Primitives (`WireTy::Prim`, go.rs:329-345)

| Rust | Swift | Note |
|---|---|---|
| `String` | `String` | |
| `bool` | `Bool` | |
| `u8`/`u16`/`u32`/`u64` | `UInt8`/`UInt16`/`UInt32`/`UInt64` | Exact widths, like Go. The hand binding also uses `UInt32` for token counts (Types.swift:159-170). JSONDecoder rejects out-of-range values and fractions, as serde does. |
| `usize` | `UInt64` | Same as Go (`uint64`). |
| `i8`..`i64`, `isize` | `Int8`..`Int64`, `Int64` | |
| `u128`/`i128` | not emitted | No use in aimux-core. The emitter errors if one appears, rather than silently using a lossy `Double`/`Decimal` (Go uses `json.Number`, go.rs:340). |
| `f32`/`f64` | `Float`/`Double` | |

### Any JSON (`WireTy::Json`, `Tuple`, unknown `Named`; go.rs:350,355)

`JSONValue`, a runtime enum like the hand binding's (Types.swift:29-58), with integer cases added (**ruled**):
`null | bool | int(Int64) | uint(UInt64) | number(Double) | string | array | object`.
- **Decode order** inside `JSONDecoder`'s single-value container: `decodeNil`, String, array, object, then **Bool → Int64 → UInt64 → Double**. The public `Decoder` API cannot see the raw number text, and no custom JSON parser will be written.
- **Big-integer precision is a hard requirement:** 2^53+1 and u64::MAX must come back exactly, as `serde_json::Value` keeps them as i64/u64. The hand type stores every number as `Double` (Types.swift:32,44), so integers above 2^53 lose precision; the verdict for such rows is **手写错**.
- **Possible known difference (not "consistent with serde"):** serde keeps `1.0`, `1e3` and `-0.0` as f64, but Foundation may decode them through the `Int64` branch, writing `1`, `1000`, `0`. This is a Foundation limitation, not settled until measured.
  - If it is confirmed after the toolchain install (`1.0` is the first measurement), the diff stays strict, with no number normalization.
  - Those rows then get the verdict **已知差异**, referencing entry `KD-SWIFT-NUM-1` in `docs/plan/2.2-known-differences.json` (see "Verdicts" below).
- **Fixtures** (real aimux-core value, numbers inside a JSON field such as `Usage.raw`): `-1`, `i64::MIN`, below `i64::MIN` (`-9223372036854775809`, f64 in serde), `2^53+1`, `u64::MAX`, `0.5`, `1.0`, `1e3`, `-0.0`.
- **Mutation:** drop the `int`/`uint` cases, so everything goes through `Double`. The 2^53+1 and u64::MAX fixtures must go red.
- `Tuple` is mapped to `JSONValue` like Go's `json.RawMessage`. No tuple is used today.

### Arrays, maps, nullable (`Array`, `Map`, `Nullable`)

| IR | Swift |
|---|---|
| `Array(T)` | `[T]` |
| `Array(u8)` (Rust `Vec<u8>`) | `[UInt8]`. See "Bytes" below. |
| `Map{String, V}` | `[String: V]` (keys are always strings on this wire, as with Go `map[string]V`). |
| `Nullable(T)` (an Option in a nested position, e.g. a map value) | `T?` inside the container: `[String: EvaluationInput?]`. Swift's synthesized container coding of an `Optional` element writes and reads `null`, as serde does. |

### Bytes (`Vec<u8>`): number array, D33 pending

Current behaviour, pinned by the Go tests: serde writes `Vec<u8>` as a JSON array of numbers. D33's text now lives in the repo as an excerpt in `docs/plan/2.2-provenance.md` (provenance: aimux-plan DECISIONS.md, outside the repo). The Swift verdict reasons for byte rows will cite "见 docs/plan/2.2-provenance.md D33（待 Trey）".
- **2.2 follow-up (not done here):** the merged Go verdicts (`docs/plan/2.2-diff-go-verdicts.json`, #54) still cite "见 aimux 计划 DECISIONS D33（待 Trey）", which points outside the repo. Switching them to the in-repo excerpt is left as a follow-up, because #54's files are not edited in this PR.

- Swift `Data` is the trap: `JSONEncoder`'s default `dataEncodingStrategy` is `.base64`, so a `Data` field writes `"AAH/"`, the same bug as Go `[]byte`. The generator never emits `Data`.
- `[UInt8]` is synthesized-Codable as an unkeyed container of numbers: `[0,1,255]`. Decoding rejects `null` elements and values above 255. So unlike Go, no wrapper type is needed. `[UInt8]` already plays the role of Go's `[]U8` (go.rs:81, :351), and the hand binding uses it too (FileBytes.binary, Types.swift:379-398; VideoData.binary, Multimodal.swift:631-650; AudioData = FileBytes, Multimodal.swift:524).
- **Ruled:** D33 stays pending. A `public typealias WireBytes = [UInt8]` is emitted, and every `Vec<u8>` field uses it, so the D33 decision later switches the representation in this one place.
- Required test, mirroring Go: AudioData/VideoData binary fixtures must, after decoding the generated Swift's output, be **equal as `serde_json::Value`** to serde's output (serde_json is built with `preserve_order`, Cargo.toml:53, so key order is kept), and must be read back by serde as `Binary`. Mutation: change the mapping to `Data` and both go red.

### Records (`WireBody::Record`, go.rs:379-421)

A `struct` with explicit `CodingKeys`. Presence decides how each field is stored, decoded and encoded:

| Presence | Swift property | Decode | Encode |
|---|---|---|---|
| required (`!omittable && !nullable`) | `T` | `decode` (missing key or `null` → error, as serde) | `encode` |
| `omittable` only (`#[serde(default)]`, not an `Option`; wire.rs:348) | `T` (default value) | `c.contains(k) ? try c.decode(T.self, forKey: k) : default`. A present `null` is **rejected**, not treated as missing: serde errors on `null` for a `#[serde(default)] Vec`/`bool`/struct, and Go rejects it with `rejectNull` (go.rs:158). `decodeIfPresent` would wrongly accept it. | `encode` (serde always writes it) |
| `skip_if_empty`, not nullable (e.g. `Vec` with `skip_serializing_if = "Vec::is_empty"`; `omittable` and `skip_if_empty` both come from `omit_when_empty`, wire.rs:348,351) | `T` | `c.contains(k) ? try c.decode(T.self, forKey: k) : empty`. A present `null` is **rejected**, as in serde. The null-alignment fixture and its mutation cover this row too. | write only when not empty |
| `nullable`, not `skip_if_empty` (`Option<T>` without skip) | `T?` | `decodeIfPresent` | **`encode(x)` or `encodeNil`**: serde writes `null`, so synthesized `encodeIfPresent` would be wrong. |
| `nullable` + `skip_if_empty` (`Option<T>` with `skip_serializing_if = "Option::is_none"`) | `T?` | `decodeIfPresent` | `encodeIfPresent` |
| `tri_state` (a `TriState` field type **with a codec**, wire.rs:358-360: `tri_state = f.codec.is_some()`; otherwise it is an ordinary nullable) | `TriState<T>` (runtime enum `.absent / .null / .value(T)`) | `contains` → `decodeNil` → value | absent: skip; null: `encodeNil`; value: `encode` |

Because of the `encodeNil` and default rows, every record gets a hand-emitted `init(from:)` and `encode(to:)`. Nothing relies on synthesized Codable, so the behaviour is explicit and diffable.

Nullability comes only from the Rust type: `nullable` is set for `Option` (and `TriState`) fields (wire.rs:353-361). `#[serde(default)]` alone sets only `omittable` (wire.rs:348).

Null-alignment fixture (planned): a non-`Option` `#[serde(default)]` field given `null`, e.g. `{"supports_images": null}` for `DecisionCapabilities` (`supports_images: bool` with `#[serde(default)]`, decision_model.rs:362-363; this struct has no `rename_all`, so the key is snake_case). serde rejects it, and the generated Swift must reject it too.

Example, 节选 (excerpt; `ImageResult` at image_model.rs:183 also has `provider_metadata` and `response`): `warnings` is a required `Vec`, `usage` is an Option with skip.
```swift
public struct ImageResult: Codable, Equatable, Sendable {
    public var images: ImageOutputs
    public var warnings: [Warning]
    public var usage: ImageUsage?
    enum CodingKeys: String, CodingKey { case images, warnings, usage }
    public init(from d: Decoder) throws {
        let c = try d.container(keyedBy: CodingKeys.self)
        images = try c.decode(ImageOutputs.self, forKey: .images)
        warnings = try c.decode([Warning].self, forKey: .warnings)
        usage = try c.decodeIfPresent(ImageUsage.self, forKey: .usage)
    }
    public func encode(to e: Encoder) throws {
        var c = e.container(keyedBy: CodingKeys.self)
        try c.encode(images, forKey: .images)
        try c.encode(warnings, forKey: .warnings)   // [] is written, like serde
        try c.encodeIfPresent(usage, forKey: .usage)
    }
}
```
The hand binding has `warnings: [Warning]` non-optional (Multimodal.swift:587), which is right here. The diff will show where other hand types use `T?` with synthesized `encodeIfPresent` against a serde `null`.

Field `aliases` (serde `alias`): the IR carries them (wire.rs:94). No aimux-core field uses one today. If present, decode tries the main key, then each alias (`AnyCodingKey`, as in the hand binding, Types.swift:86).

- `Alias(Named | Json | Tuple)` becomes `public typealias X = Y`.
- `Alias(prim/array/map)` becomes `public typealias X = <swift type>` too. Go makes a distinct named type here; Swift typealiases keep the hand-binding style (`ProviderMetadata`, Types.swift:80).
- Proxies (`from`/`into`/`try_from`): the IR already gives the wire shape. `Size`/`AspectRatio` (shared.rs:146,224) are `String` on the wire and become `typealias Size = String`. `AiMuxError` (error.rs:174) takes the shape of `AiMuxErrorWire`. The fixture test runs real proxied values through serde, as in Go (d).

### Flatten

Expanded in the IR (wire.rs:304-313): flattened fields are plain record fields. Nothing Swift-specific. aimux-core has no `#[serde(flatten)]` today (test `no_committed_type_uses_flatten`).

### String enums (`WireBody::StringEnum`, go.rs:423-442)

- **Closed:** `public enum X: String, Codable, Sendable { case stop; case contentFilter = "content-filter" ... }`. The synthesized `RawRepresentable` decode rejects unknown strings, like serde and like Go's closed check.
- **Open** (`#[serde(other)]`: Modality, ModelType, ReasoningMode, ReasoningVisibility): `public struct X: RawRepresentable, Codable, Hashable { public var rawValue: String }` with `static let` constants. Any string decodes and re-encodes verbatim. **Ruled:** keep the received string, the same as Go (`type X string` with no validation, go.rs:433-435). Serde maps an unknown string to the `other` variant and re-serializes that variant's name, so Go and Swift share this difference from serde. It is a design choice, not a platform limitation, so it can never be recorded as 已知差异. The fixtures use only declared values for open enums, so no row arises.
- **Variant aliases** (ModelType ImageGen/ImageEdit): decode accepts each alias and maps it to the main case. Encode writes the main name (go.rs:523).

### Unions (`WireBody::Union`, go.rs:466 on)

All are `public enum X: Codable, Equatable, Sendable` with hand-emitted `init(from:)`/`encode(to:)`. Payload types: a `Fields` variant gets a nested struct `X.<Variant>` (Go: `XVariant`) with the record rules above. A `Value(T)` variant gets an associated value. `Unit` has no payload.

- **Internally tagged** (`Internal{tag}`; 30 in the IR, including the `AiMuxError` proxy): read the `tag` key as `String` (missing → error), switch on it, decode the payload struct from the same container (`try X.Text(from: decoder)`), and unknown tag → error unless `other`. Encode writes the tag key first, then the payload's keys into the same keyed container (Go: `withTag`, go.rs:217). **Not verified:** the comparison is on `serde_json::Value`, and Map equality ignores key order, so the tag's position is not checked. No assertion is added for it (as in Go). A `Value(T)` payload in an internal enum must itself be an object, as in serde.
  ```swift
  case "text": self = .text(try Text(from: d))
  ...
  case .text(let p): var c = e.container(keyedBy: AnyCodingKey.self)
                     try c.encode("text", forKey: "type"); try p.encode(to: e)
  ```
- **Externally tagged** (`External`; 19 enums, **all** unit-only): unit variant ↔ `"name"`; payload variant ↔ `{"name": payload}` (single-key object). Unit-only external enums are emitted as closed string enums. The payload path is unused in aimux-core, so like adjacent it gets one **synthetic emitter unit test** (`{"name": payload}` both ways) and no wire fixture.
- **Adjacently tagged** (`Adjacent{tag, content}`): `{"tag": "...", "content": payload}`. It is supported because the IR has it and Go handles it (go.rs:556), but no type uses it, so it gets one synthetic emitter unit test and no wire fixture.
- **Untagged** (`Untagged`; 12 enums: FileBytes, AudioData, AudioInput, AudioChunk, ImageFileData, ImageOutputs, VideoFileData, EvaluationInput, DecisionValue, DecisionDescription, MessageContent, ModelPrompt):
  - Try each variant **in serde declaration order** with a strict decode, and take the first that succeeds. Example: `ImageOutputs` `[]` is `Base64`, exactly like serde and the Go overlap fixture.
  - Strictness comes from `JSONDecoder` itself: a non-optional `String`/`[UInt8]`/struct decode of `null` throws, and so does a `null` element in `[UInt8]`/`[String]`. So the top-level `null` and `[null]` rejection that Go needed `rejectNull` for (go.rs:158) falls out naturally. Records decode required keys strictly, so `wireRequired` (Go) is implicit.
  - Must be verified, not assumed: the null-parity fixtures from Go (`untagged_decode_rejects_null_exactly_like_serde`, 15 inputs) run unchanged against Swift, with an explicit mutation (an `Optional`-typed arm) shown to go red.
  - Audit result from Go (2.2-codegen-go PR body): no untagged enum has a unit variant or a bare `serde_json::Value` payload, so no arm accepts `null`. This is the premise for having no `rejectNull` in Swift, so it becomes a **test**.
    - It scans the IR, **expanding `Alias` bodies first**: `DecisionState`, `TextContentBinding` and `ToolChoice` are `Alias(Json)`, `type X = json.RawMessage` in the Go output, so `Value(Named("DecisionState"))` counts as Json.
    - It asserts that no `Untagged` variant body is `Unit`, `Value(Json)` or `Value(Nullable(_))` (null-accepting), after expansion.
    - Mutation: a synthetic IR with an untagged variant `Value(Named("DecisionState"))`. Test `untagged_variants_reject_null_premise` goes red with `untagged <Type>::<Variant> accepts null (Json after alias expansion)`. A second variant `Value(Nullable(String))` gives `... accepts null (Nullable)`.
  - Encode writes the payload directly (single-value container).
  ```swift
  public init(from d: Decoder) throws {
      let c = try d.singleValueContainer()
      if let v = try? c.decode([UInt8].self) { self = .binary(v); return }   // declaration order
      if let v = try? c.decode(String.self)  { self = .base64(v); return }
      throw DecodingError.dataCorruptedError(in: c, debugDescription: "FileBytes: no variant matched")
  }
  ```
- **`#[serde(other)]` in a tagged union:** unknown tag → `.other` (no payload), as in Go (go.rs:540).
- **Variant-level `#[serde(untagged)]`** inside a tagged enum: not used in aimux-core. The emitter errors, as Go's comment notes (go.rs:538).

### Verdicts (third verdict 已知差异, ruled in aimux-plan PHASES.md:307, 2026-10-12; aimux-plan is the RFC planning tree, not part of this repo)

- **手写错:** the hand-written Swift differs from serde, and the generated Swift matches serde.
- **生成器错:** never appears in the table. As in Go (`generated_go_matches_rust_and_diff_doc_is_current` asserts `gen_mismatch` is empty), `wire_diff_swift.rs` fails on any generated-vs-serde difference **before** the table is built, so a generator error cannot be hidden by a verdict.
- **已知差异:** only for generated code that **cannot** match serde because of a platform limitation. The sole candidate is Foundation `JSONDecoder` number parsing (`1.0` / `1e3` / `-0.0` possibly taking the `Int64` branch, see JSONValue above), and only if measured on the toolchain.
  - **Registry:** `docs/plan/2.2-known-differences.json` is machine-readable; tests never parse Markdown. Each entry has `id`, `language`, `limitationSource`, `phasesExcerpt` and `scope`.
    - `phasesExcerpt` is a verbatim quote of aimux-plan PHASES.md:307. PHASES is provenance only, and the in-repo excerpt is authoritative (also kept in `docs/plan/2.2-provenance.md`).
    - `scope` is a list of `{fixture label, leaf JSON path}`.
    - It holds `KD-SWIFT-NUM-1` (status `planned-unmeasured`, scope `json-number-1.0` / `json-number-1e3` / `json-number-neg-zero` at `raw.n`). The entry stays only if the measurement confirms it; otherwise the every-ID-referenced check forces its removal.
  - **Applies only if** the row's fixture label **and** leaf path match a scope item **and** both the generated and the serde value are JSON numbers. Every other generated difference is still a generator error, caught before the table.
  - Each verdict row with 已知差异 gives `{type, field, verdict: "已知差异", knownDifference: "<id>", reason}`. The reason names the limitation source and cites PHASES.md:307.
  - **Three-way checks, each with a mutation** (the red test is `known_differences_are_registered_scoped_and_used`):

| Check | Mutation | Expected error |
|---|---|---|
| Referenced ID exists, with matching `language` | a verdict row references `KD-SWIFT-NUM-9`, or one whose `language` is `go` | `known difference KD-SWIFT-NUM-9 not registered` / `known difference KD-… is registered for go, not swift` |
| Marked row is within scope (label + leaf path + both numbers) | mark `Usage | inputTokens.total` (a non-`raw` field of `Usage`) as 已知差异 on a json-number fixture | `known difference KD-SWIFT-NUM-1 for json-number-1.0 inputTokens.total is out of scope` |
| Every registered ID is referenced by ≥ 1 verdict row | remove all rows referencing `KD-SWIFT-NUM-1` | `known difference KD-SWIFT-NUM-1 is not referenced by any verdict` |
| No stale exemptions (kept) | mark the `0.5` fixture's `raw.n` row as 已知差异 (in scope by label/path, but it matches) | test `known_differences_still_differ`: `known difference KD-SWIFT-NUM-1: json-number-0.5 raw.n no longer differs` |

  - Generator errors are still caught earlier: the generated-vs-serde assertion in `wire_diff_swift.rs` runs before the table, as in Go, and exempts only rows that pass all the checks above.
- **No swift-format (ruled).** The gate is that the generated Swift compiles (`swift build` in the harness, warnings reported), plus `aimux-codegen --check` and `gen_closure_inventory.py --check`.

## Toolchain and where the diff runs (ruled)

- **Local Linux is mandatory.** `wire_diff_swift.rs` runs on the dev box. If `swift` is missing, the test **fails** (it is not skipped), as `wire_diff_go.rs` does for `go`.
- **Toolchain:** **Swift ≥ 6.0** required, from the official swift.org **Ubuntu 24.04** tarball (it includes swift-corelibs-foundation). It is installed on the box in a later step. Nothing is installed by this doc change.
- Current box state: `swift --version` gives `swift: command not found` (Debian 13 trixie, x86_64, 60G free on `/` when checked). The install size estimate (about 0.8–1 GB download, 2.5–3.5 GB unpacked) has not been measured yet.
- **First measurements after the install** (non-blocking until the toolchain is there):
  - exact decode on Linux of u64::MAX (`18446744073709551615`) and 2^53+1 (`9007199254740993`) through `JSONValue`
  - `0`, `1` and `true`, checking that Bool and Int decoding are mutually exclusive, so that `1` is not read as `true` and `true` is not read as `1` (the hand type's comment, Types.swift:26-27)
  - then the `1.0` / `1e3` / `-0.0` integer-branch question above
- **macOS CI is supplementary:** the existing `Swift tests` job (.github/workflows/ci.yml:414-428) runs on macos-latest. Where Darwin Foundation and swift-corelibs-foundation JSON coding differ (number/Bool coercion; the hand type's comment at Types.swift:26-27 depends on "this toolchain"), the difference is recorded in the diff doc as a note. It is **not blocking**: Linux results are the gate.
